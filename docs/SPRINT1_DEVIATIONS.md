# Sprint 1 Requirements and Verification Notes

Date: 22 October 2026. This note compares the current branch with the submitted SRS, SAD, Test Plan, and sprint backlog. It records code and verification evidence; it does not change Jira status.

| Requirement / planned design | Current implementation | Reason for difference | Impact | Future action |
|---|---|---|---|---|
| REQ-1 to REQ-7: registration, bcrypt password storage, username/email login, 24-hour JWT, lockout, authenticated WebSocket, logout | REST registration/login/logout routes now issue bcrypt hashes and JWTs; API identity comes from a signed bearer token; WebSocket auth is required within five seconds; the browser clears the token and closes its socket on logout. | The routes and timeout were absent from the starting `main`; added on this feature branch to meet Sprint 1 design. | Unit and route tests cover validation, lockout, token, and authorization. The MongoDB-backed integration test also passed in the successful GitHub Actions run for the merged PR commit. | Keep the authenticated REST and WebSocket boundaries covered by regression tests. |
| SEC-5 / SAD 4.3: identity from token; conversation access only for participants | Removed the development `x-user-id` identity fallback. Both private-conversation creation paths now use `req.userId` from the verified token. Message history checks membership. | The old fallback and legacy route trusted caller-controlled identity. | Regression tests cover anonymous access and a spoofed body `userId`. | Keep the bearer-token boundary for future REST routes. |
| REQ-8 to REQ-10 and REQ-23: private chat, real-time online delivery, message validation, persist before SENT | Existing conversation/message services remain; sender names are populated for history and live events. Browser history and message rendering now use the API and WebSocket events. The gateway closes unauthenticated idle sockets after five seconds. | The initial UI had placeholders and the gateway lacked the SAD auth deadline. | The MongoDB-backed integration test passed in GitHub Actions. It verified two authenticated users, private conversation lookup, WebSocket delivery from Alice to Bob, a `SENT` acknowledgement, message persistence in MongoDB, and message-history retrieval after an app-server restart. | Retain the integration test in CI; perform a manual two-browser demonstration for the Sprint 1 submission. |
| REQ-11, REQ-24: offline re-delivery and older-history paging | Stored messages remain available in recent history; offline recipient synchronization and cursor-based older paging are not implemented. | The repository backlog assigns offline delivery (CA-24) and older paging (CA-28) to Sprint 2. | Offline users need to reopen history; only the latest page can be retrieved. | Implement CA-24 and CA-28 in Sprint 2. |
| REQ-13: server and client sanitization | The browser renders message text through `textContent`; server-side content sanitization is not added. | CA-26 is assigned to Sprint 2 in the repository backlog. | Stored HTML is inert in the current browser renderer, but other future clients must also handle content safely. | Add consistent server-side validation/sanitization and XSS tests in Sprint 2. |
| CA-13: lint/test automation on PRs and pushes to main | Added `.github/workflows/ci.yml`; it runs unit tests, the MongoDB-backed integration test, and lint. | No workflow existed on the starting `main`. | The GitHub Actions run for the merged PR commit completed successfully, including unit tests, MongoDB integration, and lint. | Keep the workflow required for future pull requests and maintain the disposable MongoDB service used by integration tests. |
| PERF-1 / PERF-2: 95% of messages within 500 ms on LAN and 100 concurrent connections | No performance result is claimed. | The local environment has no configured MongoDB URI or load-test dataset; the backlog assigns performance/load testing to Sprint 3. | The non-functional targets remain unverified. | Run the Test Plan latency and 100-client scenarios in a configured environment. |
